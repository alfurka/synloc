# Public SIPP model-export experiment

This experiment prepares a balanced working-age panel from the public 2018 SIPP release (reference year **2017**) and evaluates parameter-only `clusterCov` models. The eight model features are four quarterly earnings sums and four quarterly means of monthly average weekly-hours rates, in original units. The experiment is unweighted and does not establish privacy clearance for confidential data.

**Executed results:** [29 October 2026 findings](RESULTS.md), with 37,552 people,
12 configurations, 120 synthetic panels, and aggregate evidence in `summary/`.
The export round trips work, but negative hours and lost zero masses are material
limitations of the unconstrained Gaussian mixture.

## Prepare the input

Run commands from the repository root with the repository environment active. Set `SIPP_INPUT` to the supplied `pu2018.csv.gz` file, or obtain the pipe-delimited GNU/Linux file from the [Census 2018 SIPP release page](https://www.census.gov/programs-surveys/sipp/data/datasets/2018-data/2018.html). The raw file need not be copied into this repository. Do not commit raw files or generated data.

```sh
python replication/model_export/prepare_sipp.py \
  --input "$SIPP_INPUT" \
  --output replication/model_export/prepared
```

`--chunksize` optionally changes the default 25,000-row input chunks. Preparation needs only pandas, NumPy, and the Python standard library. It reads ten selected columns, validates the observed panel and wave, and outputs:

| File | Contents |
| --- | --- |
| `prepared/wide.csv` | Numeric `earnings_q1` … `earnings_q4`, `hours_q1` … `hours_q4`, no IDs. |
| `prepared/long.csv` | Internal quarterly `person_id,quarter,y,h` diagnostic table. |
| `prepared/metadata.json` | Source checksum, selected fields, exclusions, zero fills, units, software versions, and limitations. |

The selected inputs are `SSUID`, `PNUM`, `SPANEL`, `SWAVE`, `MONTHCODE`, `RIN_UNIV`, `TAGE`, `RMNUMJOBS`, `TPEARN`, and `TMWKHRS`. Retained people have 12 unique months, are in the survey frame and age **18–64 throughout**, and have complete valid outcomes after documented no-job structural-zero handling. Observed negative earnings are retained because business losses are valid, not treated as invalid or clipped. There are no log transforms.

[Data-source and preprocessing details](DATA_PREPARATION.md) document the exact universes, actual hours definition, aggregation, sample selection, and bias. [`sipp_source_metadata.json`](sipp_source_metadata.json) records compact official schema/dictionary excerpts and source links. Prepared sample sizes are generated by the run, not inferred from the inspected small sample.

## Run the experiment

```sh
python replication/model_export/run_experiment.py \
  --input replication/model_export/prepared/wide.csv \
  --output replication/model_export/results
```

The default grid has **12 configurations**: requested cluster counts 20, 50, and 100 crossed with minimum contributor counts 0, 10, 50, and 100 (0 means unrestricted); each configuration uses **10 synthetic replications**. The minimum-size heuristic can reduce the realised number of clusters. These are not noise levels and do not provide differential privacy. See the driver's `--help` for available controls.

The default `prepared/` and `results/` directories are ignored, as are generated CSV and NPZ files in this directory. Keep any custom output locations ignored as well. Internal IDs, sample-flow metadata, diagnostic tables, and raw-data comparisons are not part of the parameter-only export. Export review acknowledgement is separate from mechanical model validity; public input data alone does not establish privacy approval for arbitrary fitted models.

## Evaluation and output

Each configuration fits the same estimator to the full analytical sample,
exports the original-unit mixture, checks exact seeded direct/imported sampling,
and checks the same round trip in a fresh Python interpreter. Each synthetic
replicate has the original number of people and four quarters per person.

- `models.csv`: requested and realised clusters, size range, export size, rank,
  constant-column and applicable dominance diagnostics.
- `replicate_metrics.csv` and `utility_summary.csv`: original-scale moments,
  quantiles, zero/negative rates, temporal dependence, within/between variance,
  quarterly changes, correlation errors and standardized Wasserstein distances.
- `original_metrics.json`: the original analytical-sample reference.
- `*_audit.json`: internal diagnostics; these are **not** part of the model.
- `*.npz`: research mixture artifacts, with no input rows or person IDs.
- `synthetic_panel_example.csv.gz`: one generated long-format panel with new IDs.
- `manifest.json`: input checksum, seeds, configurations, package versions.
- `utility_tradeoff.png` / `.pdf`: correlation error and fixed-effects coefficient
  error, means ± one standard deviation across ten synthetic draws, conditional
  on each fitted model. The CSV tables provide the figure's numerical equivalent.

Pooled and individual-fixed-effects regressions use quarterly earnings as the
outcome, average weekly hours as the regressor, and quarter effects. Standard
errors use a person-clustered CR0 sandwich without finite-sample adjustment.
These are descriptive preservation diagnostics, not causal estimates; synthetic
standard errors do not incorporate model-fitting or synthesis uncertainty.
Shared seeds across configurations facilitate comparisons; replicates are
independent within a configuration, not across paired configurations.

Clustering uses variance scaling but estimation/export uses original units.
There is no inverse scaling to perform outside the secure environment. We do
not clip sampled values or conceal negative hours/loss of point masses at zero.
Negative earnings can represent legitimate business losses, whereas negative
hours are invalid. Comparisons are unweighted analytical-sample comparisons,
not national population estimates.

`reviewed=True` explicitly acknowledges unresolved risks for this public-data
research experiment. It is **not approval for confidential-data release**.
Only the configured contributor check gates the research export; dominance
failures and unassessed covariance/joint-release risks remain visible.
No configuration in these results is certified disclosure-safe.
